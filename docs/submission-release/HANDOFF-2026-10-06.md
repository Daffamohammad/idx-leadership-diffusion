## 3. Code changes

### `src/idx_leadership/signals/diffusion_v2.py` (P1 root cause)

The classifier reconstructed a constituent count from breadth percentages:

```python
implied = abs(delta_pp) * group_size / 100.0   # 4.999999999999998 >= 5  → False
```

For a 45-stock group moving 16 → 21, the true count change is exactly the firm floor of
five, but the reconstructed value landed just below it, demoting `BROADENING_FIRM` to
`BROADENING_FRAGILE`. Three changes, thresholds and the 5-contributor eligibility floor
preserved:

1. **Exact integer path.** New optional `breadth_change_count` parameter. When the raw
   count change is supplied, the pp gate and firm floor are evaluated with `Fraction`:
   `100·d ≥ threshold·n` and `max(2, (n+9)//10)`. No float reconstruction.
2. **Exact floor.** `constituent_floor` now uses `Fraction(fraction).limit_denominator(10**6)`
   so `ceil(0.10·n)` cannot drift on decimal fractions.
3. **Bounded tolerance for percentage-only callers.** Retained float path compares
   `implied >= floor - 1e-9`. Reconstruction error is bounded by ~2.6e-16 · group_size
   (a few ULPs of the intermediate products), so 1e-9 absorbs it for any cohort below
   ~4 million constituents, while a genuinely sub-threshold move sits a full constituent
   (1.0) below the floor and cannot be promoted. Proved by test.

Callers updated to pass exact counts:

- `scripts/build_submission_analysis.py` — daily (line 218) and weekly (line 258) replay
- `src/idx_leadership/analytics/sensitivity.py` — sensitivity grid
- `src/idx_leadership/aggregation/groups.py` — snapshot pipeline

### `app/web/src/components/SubmissionRotationMap.tsx` (P2 display)

Added `DiffusionReading`, mirroring the existing `LeadershipReading`, so the inspector's

Backend `UNCONFIRMED` state is preserved; only rendering changed. Small groups remain

The three sites named in the audit (inspector, weekly history, table) were already
mapping leadership through `LeadershipReading` in the working tree at dispatch time; the

groups on the first replay date. Now closed.

### `tests/test_diffusion_group_size.py`

Seven boundary regressions, including the audit case n=45 16→21 and its reverse, n=19 9→11,
n=62 37→30, exact ±10 pp edges (n=20 d=2 FIRM, n=10 d=1 FRAGILE), one-name fragile moves,
sub-gate stability, missing priors, sub-five cohorts, and the float-path tolerance with a
counter-test proving a genuinely sub-threshold move is not promoted.

### `scripts/verify_diffusion_count_oracle.py` (new)

Independent integer-count oracle. Recomputes every daily and weekly state, the legacy v1
projection, and every weekly transition from stored breadth counts using pure integer
arithmetic. Never imports the production classifier. Exit code non-zero on any mismatch.

Rule, with `d` the raw count change and `n` the cohort size: broadening `10d ≥ n`,
narrowing `10d ≤ −n`, firm floor `max(2, (n+9)//10)`, `UNCONFIRMED` when the prior is
missing or `n < 5`.

## 5. Data and evidence provenance

The published package is a deliberate **two-vintage** design, and both vintages are
declared in the manifest's 124 `source_evidence` rows with hashes:

- **Primary validated panel** (2025-12-15 start) feeds `market.json`, `snapshot.json`,
  and `rotation.json`. Trailing 5d/20d/60d and the YTD base are identical under either
  vintage, so per-ticker values are unaffected.
- **September panel** (2025-09-01 start, 262 benchmark sessions) feeds the long-horizon
  replay and the 52-week high/low work. It is quarantine-derived: one ticker (`FASW.JK`)
  disagreed with the official IDX Stock Summary by 37.50 IDR and was excluded with the
  rule recorded as "retain observed source rows except the named official-price mismatch;
  do not impute missing symbols". The original FAIL validation receipt is retained
  alongside the PASS quarantine validation. No interpolation, forward-filling, or
  synthesis.

52-week comparisons exclude the selected session from its prior range, require a strict
break, and treat ties as non-qualifying. A calendar cutoff falling between sessions does
not invalidate otherwise complete history.

## 7. Known limitations and follow-ups

1. **`dist/` is a build-time copy.** `npm run preview` serves `app/web/dist/`, which
   embeds its own copy of `releases/active.json`. After any activation, run
   `npm run build --prefix app/web` before verifying in the browser, or the preview will
   keep serving the previous release. Recorded in `run-receipt.json`.
2. **Vite chunk advisory.** The production build emits a >500 kB chunk-size warning and
   a config-loader compatibility notice. Cosmetic; the deferred initial-download
   performance work is intentionally out of scope.
3. **Source evidence travels separately from Git.** The scoped source baseline and the
   active/rollback packages are committed on local branch
   `codex/release-handoff-2026-10-06`. The exact 136-file candidate source archive is
   stored under ignored `data/handoff/` in the original working copy; its SHA-256 and
   per-file inventory are tracked with the [Git handoff](GIT_HANDOFF-2026-10-06.md).
   Copy and verify that archive before using it from another checkout. Git preserves
   file contents and executable bits, while the archive preserves read-only mode bits.
4. **Konglo groups are not point-in-time eligible for 2 October.** The register records
   holdings as of 30 September but was available on 5 October, so the view correctly
   marks these groups as not point-in-time eligible for the target session. Unresolved
   ownership links remain in the decision ledger rather than being asserted.
5. **Mobile interaction audit was not repeated** in this pass; desktop verification
   covered the display and taxonomy interactions.
